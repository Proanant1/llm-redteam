What happens when you send an attack

      
Unprotected sends the prompt straight to the model. Protected adds up to three layers:

      
    
        
  • Harden the prompt. Adds a security policy to the system prompt and wraps outside text in tags that say "this is data, not instructions".
    • 
        
  • Scan the input. Pattern checks for known injection phrasing, including text hidden with leetspeak, letter spacing, ROT13 and base64.
    • 
        
  • Scan the output. Blocks answers that contain the secret (even spelled out or reversed), copy long stretches of the system prompt, or put data in a link or image.
    • 
      

      
What the scorecard numbers mean

      
    
        
  • Attack success is the share of attack attempts that reached their goal, with a 95% confidence interval.
    • 
        
  • Utility is the share of normal questions that were still answered correctly. Two of them look a bit like attacks on purpose, to show when a filter blocks real users.
    • 
        
  • A defense that cuts attack success but also cuts utility has a cost. The scorecard shows both so you can judge the trade.
    • 
      

      
Honest limits

      
    
        
  • The attack set is fixed and public, so a defense can be tuned to it. Real testing needs attacks you write yourself.
    • 
        
  • Attacks are single-message (plus scripted history). A patient human attacker adapts.
    • 
        
  • The filters are simple pattern checks. They miss paraphrased attacks, and the scorecard shows which ones slip through.
    • 
        
  • This page is a lab. For a real app, keep secrets out of prompts and enforce permissions outside the model.
    • 
      

      
Privacy and keys

      
    
        
  • Your key stays in this tab's memory and is sent only to the provider you selected. It disappears when you close the tab. Use a key with a spending limit.
    • 
        
  • There is no server behind this page. Nothing you type is stored or sent to the site's author.
    • 
        
  • Some providers do not allow requests from web pages (a browser rule called CORS). If a connection fails, try Ollama, Groq or OpenRouter, or run the Python version from the repository.
    • 
        
  • For Ollama, start it with OLLAMA_ORIGINS=* (or this site's address) so the browser may connect.
    • 
      

      
The Python version adds an always-on guard proxy for real apps. It sits in front of any OpenAI-compatible model and streams every decision to a live dashboard. A web page cannot run a server, so this site offers the same checks as a playground.
